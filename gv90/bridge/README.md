# GV90 공간 제어 브릿지

SIESTA 콘텐츠가 조명·커튼을 실제로 움직이게 하는 서비스다.

브라우저는 보안상 시리얼 포트를 열 수 없다. 전시장 PC 에서 이 서비스를 띄우면
콘텐츠가 WebSocket 으로 보낸 명령을 장비로 옮겨 준다.

```
브라우저 (SIESTA) ──ws://127.0.0.1:8090──▶ 브릿지 ──┬─ DMX512   천정 조명
                                                     └─ RS-485   커튼 모터
사운드는 PC 오디오 출력 ──────────────────────────────▶ BeoLab 50
```

사운드만 경로가 다르다. 브라우저가 PC 오디오로 직접 재생하고, 그 출력이
BeoLab 50 에 물린다. 브릿지는 재생 시점만 기록한다.

---

## 설치

전시장 PC 에 **Node.js 18 이상**이 필요하다.

```bash
cd bridge
npm install
cp config.example.json config.json
```

`config.json` 을 현장 값으로 채운다. 채워야 하는 것은 세 가지다.

1. **시리얼 포트 이름** — `node test.js --ports` 로 확인한다
2. **조명 DMX 채널 패치** — 조명의 시작 주소와 채널 배열
3. **커튼 RS-485 프레임** — 모터 제조사 프로토콜

---

## 실행

```bash
node server.js
```

```
[10:20:31] DMX Enttec → COM3
[10:20:31] 커튼 RS-485 → COM4 @ 9600
[10:20:31] GV90 공간 제어 브릿지 실행 중 — ws://127.0.0.1:8090
```

한 장비가 안 붙어도 나머지는 계속 돌아간다. 콘텐츠도 브릿지가 없으면
명령을 기록만 하고 화면은 그대로 진행하므로, 하드웨어 반입 전에 화면부터
점검할 수 있다.

`http://127.0.0.1:8090/` 을 열면 현재 상태가 JSON 으로 나온다.

## 설치 현장에서 — 배선 점검

콘텐츠를 띄우지 않고 장비만 따로 확인한다. 설치 첫날 가장 먼저 돌리면 좋다.

```bash
node test.js --ports                 # 연결된 시리얼 포트 목록
node test.js --sweep                 # 조명 채널을 1개씩 훑어 패치 확인
node test.js --dmx "#FCC77B" 0.9     # 그 색으로 켜 보기
node test.js --dmx off               # 끄기
node test.js --frames                # 커튼 프레임을 CRC 까지 계산해 보여주기
node test.js --curtain open          # 커튼 개방
node test.js --curtain close         # 커튼 닫힘
```

`--sweep` 은 채널을 하나씩 255 로 올리며 1.5초씩 머문다.
켜지는 순서와 실제 색이 설정의 `channels` 배열과 맞는지 눈으로 확인한다.

## 조명 (DMX512)

두 가지 경로를 지원한다.

| driver | 쓰는 경우 |
|---|---|
| `enttec-usb-pro` | USB-시리얼 인터페이스. 전시장에서 가장 흔하다 |
| `artnet` | 이더넷 Art-Net 노드 (UDP 6454) |

```json
"fixtures": [
  { "id": "ceiling", "start": 1, "channels": ["r", "g", "b", "w", "dimmer"] }
]
```

`channels` 는 조명의 실제 채널 배열대로 적는다. 조명이 여러 대면 항목을 늘린다.

- `dimmer` 채널이 있으면 밝기를 그 채널로 보낸다.
- `dimmer` 채널이 없는 조명은 RGB 값에 밝기를 곱해 넣는다.
- `w` 채널이 있으면 RGB 의 공통분을 흰색 채널로 옮긴다.

DMX 는 상태를 유지하지 않는 프로토콜이라 같은 값을 계속 다시 보내야 한다.
`refreshMs`(기본 40ms, 25fps)마다 재전송하고, 색 전환은 그 사이를 보간해
`fadeMs` 에 걸쳐 부드럽게 건너간다.

## 커튼 (RS-485)

모터마다 프로토콜이 달라 보낼 바이트를 16진수로 적어 둔다.

```json
"appendCrc": true,
"frames": {
  "open":  "01 06 00 00 00 01",
  "close": "01 06 00 00 00 02",
  "stop":  "01 06 00 00 00 03"
}
```

`appendCrc` 가 `true` 면 Modbus RTU CRC16 두 바이트를 자동으로 붙인다.
위 예의 `open` 은 실제로 `01 06 00 00 00 01 48 0A` 로 나간다.

제조사 전용 프로토콜이면 `appendCrc` 를 끄고 완성된 프레임을 그대로 적는다.
`node test.js --frames` 로 실제 나갈 바이트를 미리 확인할 수 있다.

## 스피커 (BeoLab 50)

기본 구성에서는 브릿지가 관여하지 않는다. 콘텐츠가 PC 오디오로 재생하고
그 출력이 BeoLab 50 에 물린다.

스피커 자체의 프리셋이나 볼륨을 네트워크로 바꿔야 한다면 `config.json` 의
`speaker.enabled` 를 켜고 엔드포인트를 채운 뒤 `server.js` 의 `handle()` 에
`speaker` 명령 처리를 더한다. BeoLab 50 의 제어 경로는 제품 구성
(Beolink Converter NL/ML 유무 등)에 따라 달라 현장 확인이 필요하다.

## 자동 실행

전시장에서는 PC 를 켜면 브릿지가 먼저 뜨고 콘텐츠가 뒤따라야 한다.

**Windows** — `server.js` 를 실행하는 배치 파일의 바로가기를 시작프로그램
폴더(`shell:startup`)에 넣는다. 콘텐츠 쪽 실행 스크립트보다 먼저 뜨게 두면 된다.
콘텐츠는 브릿지가 늦게 떠도 다시 붙으므로 순서가 어긋나도 결국 연결된다.

**Linux** — systemd 유닛으로 등록한다.
