## 3. 구성

### 3-1. 전체 흐름

```
[휴대폰 브라우저]
  마이크 → 음성 변환(PCM) ─┐
                            ├─ WebSocket ─→ [Gemini Live API · 통역 모델]
  스피커 ← 통역 음성 재생 ─┘                └→ 통역 음성 + 원문·번역 자막
        ↑
        │ ① 앱 시작 시 임시 토큰 요청 (암호 확인)
        ↓
[토큰 서버 — 함수 1개]  ← API 키는 여기에만 보관
```

음성은 브라우저에서 통역 모델로 직접 오간다. 우리 서버는 임시 토큰만 발급하므로 음성이 서버를 거치지 않아 지연이 짧고, 서버가 단순하다.

### 3-2. 모듈

| 모듈 | 역할 |
|---|---|
| 화면 (UI) | 위·아래 2분할. 위쪽은 상대용(180° 회전), 아래쪽은 내 쪽. 각 절반에 말하기 버튼, 자막, 상태 표시 |
| 음성 입력 | 마이크 권한 요청, 통역 모델이 받는 형식으로 변환해 전송 |
| 음성 출력 | 받은 통역 음성을 끊김 없이 이어서 재생. 다시 듣기 지원 |
| 통역 세션 | 방향별(한→외, 외→한) 세션 2개 관리, 음성 배분, 되울림 차단, 대화 조립 |
| 엔진 접속 | 통역 모델 연결·재연결·토큰 갱신. 이 모듈만 바꾸면 다른 엔진(GPT 등)으로 교체 가능 |
| 대화 기록 | 원문·번역문을 화면에 쌓아 보여줌. 브라우저 메모리에만 보관 |
| 토큰 서버 | 암호를 확인하고 짧은 수명의 임시 토큰 발급 (엔드포인트 1개) |
| 설정 | 상대 언어, 글자 크기 |

### 3-3. 누가 말하는지 정하는 방식

폰 마이크가 하나라서 누가 말하는지 앱이 알아야 통역 방향이 정해진다.

- **기본: 자동 (버튼 없음)** — 세션 2개를 동시에 열고 같은 마이크 음성을 둘 다에 보낸다. 통역 모델은 입력 언어를 자동 감지하고, 입력이 이미 목표 언어이면 침묵하므로(`echoTargetLanguage: false`) 한 번에 한 세션만 통역 음성을 낸다.
  ```
  마이크 ─┬→ 세션 A (목표: 상대 언어)  한국어가 들리면 통역, 상대 언어가 들리면 침묵
          └→ 세션 B (목표: 한국어)     상대 언어가 들리면 통역, 한국어가 들리면 침묵
  ```
- **대체: 눌러서 말하기** — 말하는 사람이 자기 쪽 버튼을 누른다. 그 방향 세션에만 음성을 보낸다. 시끄러운 곳용.
- **되울림 차단** — 통역 음성이 스피커로 나가는 동안에는 반대 방향 세션에 마이크 음성을 보내지 않는다. 통역 음성을 마이크가 주워 되받아 통역하는 것을 브라우저 에코 제거에 기대지 않고 막는다. 말하는 사람 쪽 세션은 계속 듣는다.

### 3-4. 통역 엔진 사양

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 모델 | `gemini-3.5-live-translate-preview` — 음성 입력 → 통역 음성 + 자막, 70개 이상 언어. **미리보기 단계** | 검색 |
| 접속 주소 | `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1alpha.GenerativeService.BidiGenerateContentConstrained?access_token=…` | 공식 SDK 소스 |
| 설정 | `setup.generationConfig.translationConfig` 의 `targetLanguageCode`, `echoTargetLanguage` · `inputAudioTranscription`, `outputAudioTranscription` | 공식 SDK 소스 |
| 임시 토큰 | `POST /v1alpha/auth_tokens` (`uses`, `expireTime`, `newSessionExpireTime`). 기본 수명 30분, 발급 후 1분 안에 세션 시작 | 공식 SDK 소스 + 검색 |
| 연결 유지 | 10분마다 재연결 필요 (`sessionResumption`, `goAway`) | 검색 + SDK 소스 |
| 출력 음성 | 16비트 PCM 24kHz 모노 | 검색 |
| 입력 음성 | 16비트 PCM 16kHz 모노를 40ms 단위로 전송 (문서 권장은 100ms 단위) | 샘플레이트는 [미확인] — 실제 호출로 확정 |
| 요금 | 약 $0.037/분 (입력 $0.005 + 출력 $0.032) | 검색(제3자). 공식 가격표 [미확인] |

실제 엔진 호출은 아직 한 번도 하지 못했다(키는 정상이나 개발 환경에서 엔진에 닿지 않음 — `checks.md`). 위 사양대로 구현하고 같은 프로토콜의 가짜 서버로 검증한다.

### 3-4-1. 1초 기준을 위한 설계

1. **말하는 동안 계속 전송** — 말이 끝나기 전에 통역이 시작되게 한다(자동 방식).
2. **미리 연결** — 앱을 열 때 통역 세션을 연결해 둔다. 3분간 쓰지 않으면 끊는다.
3. **즉시 재생** — 음성을 40ms 조각으로 보내고, 통역 음성은 첫 조각이 오는 즉시 재생한다(재생 대기 20ms).
4. **자막 먼저** — 번역 자막은 도착하는 대로 화면에 띄운다.
5. **말 끝 신호** — 눌러서 말하기에서 버튼을 떼면 `audioStreamEnd`를 보내 모델이 침묵을 기다리지 않게 한다.
6. **측정 기능 내장** — 설정의 "응답 속도 표시"를 켜면 "말 끝 → 통역 음성 시작" 시간을 화면에 보여 준다. 실기기 검수에 쓴다.

### 3-5. 기술 선택

- 프런트엔드: 프레임워크 없는 정적 웹페이지 (HTML·CSS·JavaScript). 화면이 하나뿐이라 프레임워크가 필요 없다.
- 토큰 서버: 서버리스 함수 1개.
- 배포: Vercel (정적 파일 + 함수, HTTPS 자동). [추정] — 배포는 확인받고 실행
- 저장소 위치: `my-pc-manager` 저장소의 `2026.11_BH_동시통역앱/30_개발/` 아래. [추정] — 별도 저장소를 원하면 변경.

## 4. 교체 지점

코드를 고치지 않고 바꿀 수 있어야 하는 것은 설정 파일 한 곳(`config.js`)에 모은다.

- 언어 목록과 기본 언어 쌍
- 화면 문안 (버튼, 안내, 오류 메시지 — 한국어와 상대 언어 양쪽)
- 통역 모델 ID (미리보기 모델이 정식판으로 바뀔 때 대비)
- 재연결 주기, 지연 경고 기준

API 키와 접속 암호는 설정 파일이 아니라 배포 환경의 환경 변수에 둔다.

## 5. 장애 대응

| 상황 | 동작 |
|---|---|
| 마이크 권한 거부 | 권한 켜는 방법을 화면에 안내. 다시 시도 버튼 |
| 네트워크 끊김 | 양쪽 화면에 "연결 끊김" 표시 → 자동 재연결. 끊긴 동안 말한 내용은 통역되지 않았다고 표시 |
| 10분 세션 한도 | 9분째에 대화가 잠깐 비는 틈에 재연결. 재연결 중 마이크 음성은 3초분까지 모아 두었다가 이어 보냄 |
| 토큰 만료 | 연결할 때마다 새 임시 토큰을 받음 (1회용) |
| 통역 지연 (3초 초과) | "통역 중…" 표시로 기다리라는 신호를 줌 |
| 음성 인식 실패·무음 | "다시 말씀해 주세요"를 해당 화자 언어로 표시 |
| 스피커 소리를 마이크가 다시 주움 | 통역 음성 재생 중에는 반대 방향 세션으로의 전송만 멈춤. 그래도 되울리면 '눌러서 말하기'로 전환하거나 이어폰 사용 |
| 요금 초과 위험 | 접속 암호로 외부인 사용 차단. 무입력 2분이면 세션 자동 종료 |

## 6. 확인 방법

- **자동 확인 (이 개발 환경에서 가능)**: 미리 녹음한 한국어·영어 음성 파일을 가짜 마이크 입력으로 넣어 브라우저를 구동하고, 발화 종료 시각과 통역 음성 시작 시각을 로그로 비교한다. 완료 기준 1·2·5·6·7을 이 방식으로 확인한다.
- **실기기 확인 (사용자 휴대폰 필요)**: Android Chrome, iPhone Safari에서 실제로 말해 본다. 완료 기준 3·4와 소음 환경 체감은 실기기로만 확인할 수 있다. 이 개발 환경에는 마이크와 휴대폰이 없다.
- **확인 못 한 항목**은 통과로 적지 않고 `미확인`으로 남긴다.

## 7. 단계

| 단계 | 내용 | 끝나면 볼 수 있는 것 |
|---|---|---|
| 0. 사전 확인 | API 키 정상화 후, 한국어·영어 각 10문장(짧은 문장 포함)으로 "말 끝 → 통역 음성 시작" 실측. OpenAI 키가 있으면 GPT도 같이 측정 | 엔진 확정, 1초 기준 달성 여부 |
| 1. 핵심 기능 | 2분할 화면, 탭해서 말하기, 양방향 통역, 자막 | 한 폰에서 양방향 대화 |
| 2. 안정화 | 자동 재연결, 토큰 갱신, 오류 안내, 언어 선택, 대화 기록 | 15분 연속 대화 |
| 3. 배포 | HTTPS 배포, 접속 암호, 실기기 검증 | 휴대폰에서 주소로 접속해 사용 |
| 4. 선택 확장 | 자동 감지(버튼 없는 대화), 대화 기록 내보내기, 음성 교체 | 필요할 때 별도 결정 |

API 키가 막혀 있어 0단계를 뒤로 미루고 1~2단계를 먼저 구현했다(2026-11-24). 0단계 실측에서 1초가 안 나오면 기준을 낮추지 않고 측정값을 보고한 뒤 결정을 받는다.

## 9. 개인정보·비용

- 음성은 통역을 위해 Google 서버로 전송된다. 우리 서버에는 음성도 대화 내용도 저장하지 않는다.
- 대화 기록은 브라우저 메모리에만 있고 탭을 닫으면 사라진다.
- 상대에게 통역 앱 사용 사실을 알릴 수 있도록 상대 쪽 화면에 첫 안내 문구를 띄운다.
- 요금은 사용한 음성 시간만큼 나온다. 단가는 0단계에서 확인해 "10분 대화당 예상 비용"으로 보고한다.
