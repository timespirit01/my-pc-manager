# 마주 통역 — 진행 기록

## 현재 상태 (261125)

- **완성**: 모바일 웹앱 전체 (결과 위치: `../src/`)
  - 2분할 화면(상대 쪽 180° 회전), 처음 안내, 언어 선택(10개), 설정(대화 방식·글자 크기·응답 속도 표시), 어두운 화면
  - 자동 대화(세션 2개 동시 수신)와 눌러서 말하기, 되울림 차단, 다시 듣기
  - 통역 엔진 접속(Gemini Live API 통역 모델), 임시 토큰 서버, 접속 암호
  - 자동 재연결(연결 시간 한도, 끊김, 인터넷 차단), 오류 안내
  - 자동 검사 27개 + 15분 연속 대화 검사, 화면 캡처 9장(`screens/`)
- **배포 (261125)**: Vercel 프로젝트 `majoo-interpreter` (팀 timespirit's projects, GitHub `timespirit01/my-pc-manager` 연결, Root Directory `2026.11_BH_동시통역앱/30_개발/src`). 브랜치 `claude/youthful-pascal-l9ledt`를 운영 배포. 주소 https://majoo-interpreter-timespirit01.vercel.app — 화면 200, `/api/token` GET 405(함수 동작) 확인. Vercel 로그인 보호가 켜져 있어 처음 열 때 Vercel 로그인 필요
- **진행 중**: `GEMINI_API_KEY`는 등록됨(운영 환경). 재배포 후 `/api/health?engine=1` → `key:true, passcode:false, engine:ok` (실제 Google 서버가 키와 토큰 요청을 받아 줌). **`APP_PASSCODE`가 아직 없어** 앱의 토큰 발급은 거부 상태 → 사용자가 추가하면 재배포
- **남은 문제**
  - 실제 통역 엔진으로 한 번도 돌려 보지 못함. 키는 정상이지만(261125 확인) 이 개발 환경에서는 엔진에 닿지 않음: 키가 `Authorization` 헤더로만 주입되고, 웹소켓 접속은 프록시에서 404. 상세는 `checks.md`. 완료 기준 1·2(1초)와 통역 품질은 미확인
  - 실제 휴대폰(Android Chrome, iPhone Safari)에서 확인하지 못함
  - 배포는 했으나(261125) 환경 변수 `APP_PASSCODE`가 없어 통역은 동작하지 않음
  - 상대 쪽 화면 문안 10개 언어는 원어민 검수를 받지 않음
- **결과에 영향을 준 가정**
  - 내 언어는 한국어 고정, 상대 언어 10개 (사용자 확정 아님)
  - 코드 위치는 `my-pc-manager` 저장소의 `2026.11_BH_동시통역앱/30_개발/src` (사용자 확정 아님)
  - 마이크 입력은 16kHz 16비트 PCM으로 보냄. 공식 문서로 확인하지 못한 값
  - 엔진이 입력 받아쓰기에 언어 코드를 주면 그것으로, 안 주면 "통역 음성을 낸 세션의 받아쓰기만 표시"로 중복을 막음. 실제 엔진이 어느 쪽인지 모름
  - 엔진이 한 마디의 끝(`turnComplete`)을 알려 주지 않을 경우에 대비해 1.5초 동안 새 내용이 없으면 끝난 것으로 처리
  - 설계→계획 문서→착수 순서였으나, 사용자가 설계 승인과 함께 "개발 진행"을 지시해 별도 계획 문서 없이 구현함. 검사 항목은 `checks.md`
- **실패한 시도**
  - 공식 문서 사이트(ai.google.dev) 접근: 이 세션의 네트워크에서 차단됨 → 공식 SDK(`@google/genai` 3.6.1) 소스에서 프로토콜을 읽는 것으로 대체. 문서 사이트 접근은 다시 시도하지 않음
  - 가짜 서버가 말의 첫 40ms 조각만으로 언어를 판정 → 소리가 조각 중간에 시작되면 영어를 한국어로 오판해 검사가 간헐적으로 실패. 첫 조각을 빼고 120ms를 모아 판정하도록 고침 (앱 결함 아님)
  - (261125) "API 키가 막혀 있다"는 진단: 틀렸음. `API_KEY_SERVICE_BLOCKED`만 보고 판단했고 다른 인증 경로를 시험하지 않았다. 키 교체를 다시 권하지 않음
  - (261125) 보안 입력창으로 `x-goog-api-key` 헤더용 키 저장: 입력창이 이 헤더를 받지 않아 거절됨. 다시 시도하지 않음
  - (261125) 이 세션에서 통역 엔진 웹소켓 직접 접속: 프록시를 거치면 404. 다시 시도하지 않음

## 다음 행동

1. (사용자) Vercel 프로젝트 설정 → Environment Variables에 `APP_PASSCODE` 추가(Production). 그다음 재배포(환경 변수는 새 배포부터 적용) → `/api/health`에서 `passcode:true` 확인. 운영 배포는 브랜치에서 수동으로 만든다(브랜치 푸시는 미리보기 배포만 만들고, 미리보기에는 키가 없음). 무료 등급이면 통역 지연 사례가 있으니 결제 등급 확인
2. 배포본에서 실제 엔진으로 한 방향 통역 1회 시연 → 설정 메시지·음성 형식이 받아들여지는지 확인. 거절되면 화면의 오류 문구(종료 코드와 사유)를 보고 `engine-gemini.js`의 `_setup()` 수정
4. 실기기에서 "응답 속도 표시"로 한국어·영어 각 10문장 측정 → `checks.md` 1·2·4번 갱신. 1초가 안 나오면 기준을 낮추지 않고 측정값을 보고
5. 실기기에서 되울림(A6-실제) 확인. 되울리면 `config.js`의 `echoTailMs`를 늘리거나 눌러서 말하기를 기본으로
